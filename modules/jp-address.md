# Module: JP Address Forensics

このモジュールは `institutional-forensics` を、日本の住所・地番・住居表示の不整合調査に適用するためのドメイン拡張である。

Version: 0.1.1

## Domain layers

住所文字列を一つの値として扱わない。

最低限、以下を分離する。

1. 町名・丁目
2. 街区符号
3. 基礎番号
4. 住居番号
5. 土地の地番
6. 棟番号
7. 各戸番号 / 部屋番号
8. 施設全体の所在地
9. 個別建物の所在地
10. 住戸単位の正式住所
11. 施設が便宜上使用する所在地表記

例:

```text
2-1-2
```

は文脈により、

```text
2丁目1番2号
2丁目1番地2
2丁目1番2号棟
```

など異なる概念を表し得る。

## Object granularity rule

住所調査では、次の対象粒度を混同しない。

```text
敷地
施設・団地全体
個別棟
個別住戸
土地の筆
```

特に、調達資料などの

```text
楠上第二住宅　○○町1-1外
```

のような施設単位の所在地表記から、個別棟の正式な住居番号を直接推定してはならない。

`外` が付く所在地は、複数敷地・建物をまとめた業務場所の表現である可能性もあるため、個別住居番号のEvidence Class Aとしては扱わない。

## Primary sources

優先順:

1. 自治体の住居表示台帳・住居番号設定記録
2. 自治体から交付された住居番号設定通知等
3. e-Gov 法令
4. 国の住居表示実施基準
5. 自治体の条例・規則・要綱・実施基準
6. 国土地理院「住居表示住所」
7. 法務局・登記情報
8. 自治体地番参考図
9. 国・自治体・財務局等の行政資料
10. 旧版地図・航空写真・公文書

探索用:

- 地理院地図
- 民間地図サービス
- 地番可視化サービス
- 不動産データベース

探索用データを最終根拠と混同しない。

## Address-specific hypotheses

```text
H0 そもそも重複住所という前提が未確認
H1 地番住所と住居表示の混同
H2 一方が誤記 / 便宜表記
H3 基礎番号と正式住居番号の差
H4 団地 / 中高層建物の棟番号特例
H5 旧住所と新住所の混在
H6 制度上の住居番号重複
H7 各戸番号省略による見かけの重複
H8 自治体独自ルール
H9 過去の付番を維持する経過的運用
H10 施設全体と個別棟の住所粒度が異なる
```

## Critical cautions

### 基礎番号 ≠ 個別建物の正式住所一覧

国土地理院は「住居表示住所」について、基礎番号のデータであり、個別建築物を識別するものではなく、すべての住居番号に対応する基礎番号があるとは限らないと説明している。

したがって:

```text
基礎番号 != 常に正式住居番号
```

不一致を見つけても即「住所誤り」としない。

### 施設所在地 ≠ 個別棟の住居番号

行政の調達資料や資産一覧で施設全体が `1-1` とされていても、個別棟が `1-2` でないとは限らない。逆も同様。

最終的には、対象粒度が一致した住居表示台帳・付番記録などで確認する。

### 古い公式資料 ≠ 現行住所

古い行政PDFを使う場合、後続版・現行資料とのSource Driftを確認する。

## Address workflow

0. 重複・不整合という前提を対象粒度ごとに検証
1. 対象建物を別Entityとして確定
2. 施設全体 / 個別棟 / 個別住戸のどの住所かを明示
3. 位置・接道・同一街区か確認
4. 住居表示実施地区か確認
5. 街区符号・基礎番号確認
6. 地番確認
7. 問題住所の公式使用実績を対象粒度ごとに確認
8. 古い資料と現行資料のSource Drift確認
9. 住居表示法・実施基準・自治体規程確認
10. 団地 / 中高層 / 棟番号 / 各戸番号 / 枝番号の特例確認
11. 建設・移転・住居表示開始・制度改正の時系列復元
12. 必要なら住居表示台帳・付番記録・担当課照会へ進む
